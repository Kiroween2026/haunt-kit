Format: `YYYY-MM-DD | name | Kiro feature | what happened`. Add a new line as a list item (`- ...`) at the end.

- 2026-11-16 | Yadnesh | Vibe chat | Kiro checked typescript-eslint's peer range (`typescript >=4.8.4 <6.1.0`) before installing and pinned TypeScript to ~6.0.3 instead of the latest 7.x, avoiding a broken lint setup. Reason recorded in .kiro/steering/tech.md.
- 2026-11-16 | Yadnesh | Property-based testing | The Sample JSON round-trip property needs -0 normalized to 0, because JSON.stringify(-0) is "0". Harmless for sensor data; documented in packages/protocol/src/index.test.ts.
- 2026-11-16 | Yadnesh | Steering | Wrote product.md, tech.md and structure.md so every teammate's Kiro gets the same rules (privacy, iPhone limits, folder owners) from day one.
- 2026-11-17 | Yadnesh | Specs | Wrote the protocol spec (requirements, design, tasks) before code. Writing the design showed the original message list had no way for a host to create or resume a room, so create_room, resume_room and room_ready were added and flagged for review.
- 2026-11-17 | Yadnesh | Property-based testing | The round-trip property passed with the first draft's 64-sample batch limit, because fast-check generates small arrays by default. A targeted worst-case check showed 64 samples of max-length numbers are about 21 KB, over the 16 KB limit, so a batch could pass the schema and still fail encode. Lowered the limit to 32 (about 10.7 KB) and added a property test that a full worst-case batch always fits.
- 2026-11-17 | Yadnesh | Property-based testing | Added a "no player spoofing" property: any playerId a phone puts on sensor_frames or gesture is dropped by decode, so the relay can only forward input under the sender's own id.
- 2026-11-19 | Yadnesh | Property-based testing | Checked the relay's room property tests by planting bugs on purpose (color by player count instead of slot; frames stamped with the wrong player). Both were caught, but the first run showed two weak spots: the test harness kept sending from sockets the relay had already closed, and waits up to 90 s meant almost no rejoin happened inside the 60 s grace window. Fixed the harness, added waits around the 60 s and 120 s limits, and raised runs to 400.
- 2026-11-19 | Yadnesh | Vibe chat | Ran the same 7-step smoke test against the Node relay and against the Cloudflare Durable Object in `wrangler dev`. Both passed: create, join, frames stamped with the sender's id, ui, phone rejoin with the same id and color, host resume, unknown room.
- 2026-11-19 | Yadnesh | Vibe chat | CI failed on `pnpm install --frozen-lockfile` because pnpm 12 blocks install scripts by default, and wrangler needs esbuild and workerd. Approved just those two in pnpm-workspace.yaml (allowBuilds).
- 2026-11-19 | Yadnesh | Property-based testing | The protocol round-trip property failed in CI with a new random seed: a gesture with data `{"__proto__": 0}` decoded as {} because zod drops that key to block prototype pollution. A phone could send such a key, and the host would get a different message. Gesture data keys must now start with a letter, so the key is rejected instead of silently changed. Added explicit tests for the counterexample.
- 2026-11-19 | Yadnesh | Vibe chat | Controller tests for "room not found" and "room full" timed out. The client was fine; the in-memory relay (which the host-sdk MockTransport uses) dropped a message the server sent right before closing, while a real WebSocket delivers it first. Fixed the ordering and added a test, so the mock now matches the real relay.
- 2026-11-19 | Yadnesh | MCP | Built the Séance MCP server (8 tools). Tested through a real MCP client against a real relay with a ghost phone doing a ±30° tilt circle: the snapshot reported beta within ±30° and an acceleration magnitude mean of 9.81, which matches the motion. Also launched it over stdio exactly as .kiro/settings/mcp.json does and confirmed the token never appears in relay logs or error messages.
- 2026-11-19 | Yadnesh | Property-based testing | Desktop simulator motion model: properties check that gravity magnitude is always 9.81 for any mouse position, and that an untouched simulator is perfectly still (so it can never trigger shake by itself). Playwright drives the simulator page on WebKit and Chromium against the real relay: tilt frames and S/Space gestures reach the host.
- 2026-11-19 | Yadnesh | Vibe chat | Playwright e2e for the phone controller with synthetic devicemotion events. Two real findings: Chromium now has DeviceMotionEvent.requestPermission too and answers "denied" in tests unless the accelerometer/gyroscope permissions are granted (the controller showed "Motion is blocked", which is the right screen); and the test's own fake gravity was wrong, caught because the controller's frames didn't add up to 9.81.
- 2026-11-19 | Yadnesh | Vibe chat | Security pass on the relay: added a 10 s join timeout for idle sockets (checked on the Durable Object in wrangler dev too) and made the dev admin API refuse to start on a non-loopback host. Full table in docs/SECURITY.md.
- 2026-11-19 | Yadnesh | Vibe chat | The CI e2e job hung for 15 minutes after all 12 Playwright tests had passed: the dev servers were started through `pnpm`, and the wrapper didn't exit when Playwright stopped them. Now they start as plain `node` processes with graceful shutdown, and both CI jobs have a 15-minute timeout and Playwright a 10-minute global timeout.
- 2026-11-17 | Anish | Spec mode | Authored gestures spec, Ghost Recording schema, and gestures.md steering, freezing the detector contract for host-sdk and seance-party unblocking.
- 2026-11-19 | Yadnesh | Vibe chat | Checked my own synthetic data against Anish's 6 real Android recordings. The gravity formula used by the desktop simulator, the synthetic ghost recordings and the e2e fake motion had the ax and ay signs backwards: mean error 8 to 19 m/s² on tilted recordings, versus 0.04 to 0.59 m/s² with the corrected signs. Fixed all three and added a test that runs the model against every file in recordings/. The bug passed every earlier test, because those tests were written with the same wrong formula.
- 2026-11-19 | Yadnesh (built for Anish's gestures package) | Property-based testing | Built flick, spin, flip, scream, tap, rep and the catalog, with property tests for the five invariants in Anish's spec. Each property is checked by planting a bug: a spin that assumes 60 Hz, a flick with no minimum size, and a rep counter that counts tiny movements were each caught by the matching test.
- 2026-11-19 | Yadnesh (built for Anish's gestures package) | Property-based testing | Three real bugs found while building. (1) The rep detector crashed with "cannot read properties of null" on the first sample: a unit vector can have a norm of 0.99999999, and my free-fall guard (magnitude under 1) rejected it. (2) A flick made during the cooldown was reported late, the moment the cooldown ended, because it stayed in the buffer. (3) The "reps count exactly N" property failed at 60° because the target for full range is 70°; the test, not the detector, was wrong.
